# Concerns

## Status
The repo is effectively greenfield — there is little "tech debt" because there is little tech. Most concerns are forward-looking and relate to the gap between the README promise and the prototype.

## Promise vs. Reality Gap
| README promise | Reality in `poc/` |
|---|---|
| "Upload a photo of your room, then drag in cushions, furniture, and wall art" | Only cushions are wired into the prototype (`Cushion Stylist`). Furniture and wall art are unimplemented. |
| "Backgrounds are removed automatically so everything sits naturally in the space" | No background removal anywhere — cushions are placed as-is. |
| "design your room before you buy a thing" | No catalog, no commerce, no product source. |

## Prototype-Specific Concerns
- **`poc/support.js` is non-production code.** It is generated by a sibling `dc-runtime` project and ships React-runtime assumptions that only the Claude.ai artifact host satisfies (`window.React`/`window.ReactDOM` injection). Anyone double-clicking the file locally will see nothing.
- **`poc/Cushion Stylist (shareable).html` is a 245 KB self-contained file.** Convenient for showing the idea, but it is a frozen snapshot — changes in the `.dc.html` source do not propagate.
- **Filenames contain spaces and parentheses** (`Cushion Stylist (shareable).html`) — these will trip up shell scripting and URL routing if treated as production assets.
- **No persistence.** Refreshing the page drops the room photo and all placed cushions.
- **No mobile considerations.** Inline drag-and-drop with `draggable="true"` does not work on touch devices without explicit handling.

## Security
- No secrets in repo. Clean.
- Once a backend exists, file uploads (room photos) become an obvious upload-validation / content-moderation surface — flag now.

## Performance
- N/A at this stage. The future background-removal step is the obvious performance hotspot to design around (model size, cold start, mobile RAM).

## Missing Foundations
- No `package.json` / dependency manifest.
- No README beyond a one-sentence pitch — no setup, run, or contribute instructions.
- No license file.
- No `.gitignore` for the production stack (the existing one, if any, has not been verified for the chosen framework).

## Notes for Planning
- Treat `poc/` as a UX reference artifact, not a starting point for the codebase. The first phase should stand up the real project skeleton from scratch.
- The background-removal feature is the riskiest open question — surface it early in roadmap discussion.
