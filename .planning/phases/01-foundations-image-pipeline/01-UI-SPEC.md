# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1 (Foundations & Image Pipeline). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of visual direction:** `poc/Cushion Stylist.dc.html` (the prototype is the UX spec per CLAUDE.md). Tokens below are extracted from the POC's inline styles and rounded onto an 8-point scale.
>
> **shadcn gate result:** declined for Phase 1. The POC establishes a bespoke warm-neutral palette + Marcellus/Mulish typography that does not align with shadcn's default neutral system; the editor is canvas-based (Konva) so a heavyweight component library would be over-scoped for a phase that ships only a shell, an upload dropzone, an error toast, and a footer. Revisit at Phase 5 (onboarding components) if needed.

---

## Phase 1 UI Surface (in scope)

The contract below covers only what Phase 1 actually renders:

1. **App shell** — header (logo + wordmark + tagline), main stage area, footer with "Open source" link
2. **Empty state (no room photo yet)** — dashed dropzone with icon, headline, helper copy, primary CTA button, hidden `<input type="file" accept="image/*" capture="environment">`
3. **Room photo present state** — full-bleed image inside rounded card with shadow, with a single secondary action ("Change room photo") in the header
4. **Error toast / inline error** — friendly HEIC rejection + generic upload failure
5. **Hydration skeleton** — placeholder shown for one paint while IDB blob resolves
6. **Safe-area handling** — `viewport-fit=cover`, `100svh`, `env(safe-area-inset-*)` padding

Out of scope this phase: library, drag/drop placement, selection toolbar, export, BG removal, onboarding tooltip.

## Spacing Scale

Declared values (all multiples of 4, derived from the POC's inline padding/gaps):

| Token | Value | Usage in Phase 1 |
|-------|-------|------------------|
| xs    | 4px   | Gap between icon + label inside CTA, fine-grained vertical rhythm in tagline |
| sm    | 8px   | Gap between header action buttons; vertical gap inside footer |
| md    | 16px  | Default control padding; gap between dropzone icon and headline |
| lg    | 24px  | Empty-state internal padding; footer vertical padding |
| xl    | 32px  | Header horizontal padding (desktop); main stage padding (desktop) |
| 2xl   | 48px  | Major vertical breathing room above empty-state dropzone on desktop |
| 3xl   | 64px  | Reserved (not used in Phase 1; declared for downstream phases) |

Exceptions:
- **Touch targets:** minimum 44×44px (Apple HIG) for the header "Change room photo" button and the footer "Open source" link. Inner padding may visually read smaller; hit area must be 44px regardless.
- **Safe-area insets:** header `padding-top` adds `env(safe-area-inset-top)`; footer `padding-bottom` adds `env(safe-area-inset-bottom)`. These are additive and not part of the 8-point grid.

## Typography

Exactly 4 sizes, exactly 2 weights (Mulish 400 + Mulish 700; Marcellus is a single-weight display face and does not count toward the weight budget per the "2 weights of the body face" rule).

| Role     | Family    | Size  | Weight | Line Height | Usage in Phase 1 |
|----------|-----------|-------|--------|-------------|------------------|
| Body     | Mulish    | 16px  | 400    | 1.5         | Empty-state helper copy, error toast body, footer text |
| Label    | Mulish    | 14px  | 700    | 1.4         | Button labels ("Choose photo", "Change room photo", "Open source") |
| Heading  | Marcellus | 22px  | 400    | 1.2         | Empty-state headline ("Upload a photo of your room") |
| Display  | Marcellus | 28px  | 400    | 1.1         | Wordmark "RoomDrop" in header |

Notes:
- Mobile: body and label sizes stay constant (16px is the iOS auto-zoom threshold); heading scales down to 20px below 360px width via a single `clamp(20px, 5vw, 22px)`.
- Tagline ("Style your room, one piece at a time") uses Body 14px/1.4 in muted color — counts as label role, not a new size.
- All sizes declared in `px` in tokens; consumed via Tailwind's `text-[size]` utilities.

## Color

Palette extracted from the POC and normalized. The 60/30/10 split is honored on the **app chrome**, not the room photo (which is user content and dominates the stage by design).

| Role             | Token       | Hex      | Usage |
|------------------|-------------|----------|-------|
| Dominant (60%)   | `--bg`      | `#f1ebe1` | App background behind the stage; page body |
| Secondary (30%)  | `--surface` | `#fbf8f2` | Header bar, footer bar, empty-state dropzone fill, toast surface |
| Accent (10%)     | `--accent`  | `#c17a52` | **Reserved for** (exhaustive list, Phase 1): (1) "Choose photo" primary CTA fill, (2) logo mark square in header, (3) focus ring on focused interactive elements |
| Destructive      | `--danger`  | `#b5573f` | **Reserved for** (Phase 1): error toast left accent bar + error toast icon color. No Phase 1 destructive actions yet (Phase 3 introduces "Reset everything") |
| Ink (text)       | `--ink`     | `#3a332c` | Primary text |
| Ink-muted        | `--ink-mut` | `#9a8f7f` | Tagline, helper copy, footer text |
| Ink-faint        | `--ink-fnt` | `#b3a890` | Disabled state, hint overlay |
| Border           | `--border`  | `#e4dccf` | Hairline dividers, button borders |
| Border-dashed    | `--border-d`| `#cdbfa8` | Dropzone dashed outline |

Contrast check (WCAG AA, normal text):
- `--ink` on `--bg`: 9.8:1 ✓
- `--ink` on `--surface`: 10.4:1 ✓
- `--ink-mut` on `--surface`: 3.4:1 ✓ (large-text-only; only used at 14px+ in muted-helper role)
- `#ffffff` on `--accent`: 4.6:1 ✓ (CTA label on accent fill)
- `#ffffff` on `--danger`: 5.1:1 ✓

Focus ring: 2px `--accent` outline + 2px transparent offset, applied via `:focus-visible` only.

## Copywriting Contract

All copy locked for Phase 1. Voice: warm, plainspoken, second person, no marketing-speak. No emoji in copy (the dropzone uses an icon, not an emoji, despite the POC).

| Element | Copy |
|---------|------|
| Wordmark (header) | `RoomDrop` |
| Tagline (header, desktop only) | `Preview a piece before you buy it` |
| Primary CTA (empty state, button label) | `Choose photo` |
| Empty state heading | `Upload a photo of your room` |
| Empty state body | `A clear shot in good light works best. Your photo stays on this device — nothing is uploaded.` |
| Empty state secondary line (mobile camera affordance) | `Tap to open camera or photo library.` |
| Replace-photo action (header, when room loaded) | `Change room photo` |
| Hydration skeleton aria-label | `Loading your room photo` |
| HEIC error (toast title) | `That photo format isn't supported yet` |
| HEIC error (toast body) | `iPhone HEIC photos can't be opened in the browser. In Photos, tap Share → "Save to Files" as JPEG, then upload that.` |
| Generic upload error (title) | `Couldn't open that photo` |
| Generic upload error (body) | `The file may be corrupted or too large. Try a different photo.` |
| Toast dismiss aria-label | `Dismiss` |
| Footer link | `Open source` (links to repository README; opens in new tab, `rel="noopener"`) |
| Footer surrounding text | `RoomDrop is ` **Open source** ` under AGPL-3.0` |

Destructive confirmations (Phase 1):
- None. "Change room photo" is the only mutating action and **does not** prompt in Phase 1 (per Phase 3 success criteria, the confirmation pattern lands in Phase 3). Phase 1 contract: tapping "Change room photo" immediately opens the file picker and silently replaces the active photo on successful selection. The previous blob is discarded.

Microcopy rules:
- Sentence case for buttons and headings (never Title Case, never ALL CAPS).
- No exclamation marks anywhere in Phase 1.
- Error copy always names the cause then the next step, in that order.

## Interaction Contract

| Surface | Trigger | Result |
|---------|---------|--------|
| Empty-state dropzone | tap / click | Opens native file picker (`accept="image/*"`, mobile adds `capture="environment"`) |
| Empty-state dropzone | drag file over (desktop) | Border switches to `--accent`, fill tints 5% toward `--accent` |
| Empty-state dropzone | drop file | Same handler as picker selection |
| "Change room photo" button | tap / click | Opens picker; on success, new photo replaces the active one with a 150ms cross-fade |
| Toast | tap dismiss | Removes toast immediately |
| Footer "Open source" link | tap / click | Opens repository in new tab |
| Anywhere | reload (Cmd-R / pull-to-refresh) | Skeleton paints first; IDB blob hydrates; cross-fades to `<img>` once decoded |
